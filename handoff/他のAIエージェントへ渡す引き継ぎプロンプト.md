# コンテンツの安全ルール

自著とKindEd共著本を、依頼制作のデザイン実績へ混ぜないでください。KindEd共著本は自著棚とは別に扱い、現在は6冊です。YouTubeは現在約4本表示する構成です。

Amazonリンクは、表紙・正式タイトル・著者名・ASINが一致して確認できた場合だけ直リンクにしてください。確認できない場合はAmazon検索リンクを使い、ASINを推測しないでください。アフィリエイトリンクは既存の共有関数を使ってください。

ココナラのレビューや評価は、公開ページで実際に確認できたものだけを使ってください。現在、商品別レビューを表示する対象は出版サポートと表紙デザインです。レビューがない商品へ、架空の感想・評価・星の数を追加してはいけません。掲載する場合は商品に紐づけ、購入者名・評価・引用元URLを確認してください。

外部サイトの情報を使ったら、確認URL、確認日、確認内容をresearch/へ記録してください。文章を転載しすぎず、必要な場合は出典に基づく短い要約へ整えてください。

# 画像の扱い

画像や動画をclient/public、client/src/assets、リポジトリ直下へ保存しないでください。元ファイルは/home/ubuntu/webdev-static-assets/に置き、永続ストレージURLを参照してください。提供された猫アイコンは、ヘッダーやプロフィールなど意味のあるブランド用途を優先します。本文途中に理由なく猫画像を置かないでください。装飾用シルエットや足跡にはaria-hidden="true"、pointer-events:none、低い不透明度を使い、prefers-reduced-motionにも配慮してください。

# HTML・UI・アクセシビリティ

<a>の中に別の<a>を入れないでください。カード内にレビュー出典リンクや詳細リンクがある場合、カード全体を外側のリンクにせず、divと独立したリンクで構成してください。

画像には内容に合うaltを付け、ボタンには具体的なラベルを付けてください。キーボード操作、フォーカス表示、スマートフォン幅での読みやすさを確認してください。書籍要約は長文をそのまま並べず、既存のアコーディオンや短い初期表示を使ってください。アニメーションは短く、reduced-motionで抑制してください。

# 典型的な更新手順

## 書籍を追加・修正する場合

1. 公式Amazonまたは公式サイトで正式タイトル・著者・表紙・ASINを確認する。
2. research/へ出典を記録する。
3. 自著、KindEd共著、デザイン実績のどれかを決める。
4. shared/const.tsの適切な配列だけを編集する。
5. 画像URL、Amazonリンク、要約、対象読者タグを確認する。
6. Home.tsxで表示崩れがないか確認する。
7. 型チェック、テスト、ビルド、デスクトップ・モバイル表示を行う。

## YouTubeを更新する場合

1. 公式チャンネルで動画IDと正式タイトルを確認する。
2. YOUTUBE_VIDEOSを更新し、動画IDから公式サムネイルを設定する。
3. 表示本数が約4本であることを確認する。
4. YouTubeへのリンク、サムネイル、alt、モバイル表示を確認する。

## KindEdイベントを更新する場合

1. KindEd公式サイトとPeatix公式ページを確認する。
2. 新しいイベントだけでなく、必要に応じて過去イベントも日付順に整理する。
3. KINDED_EVENTSへ日付、タイトル、概要、種別、公式URLを登録する。
4. Peatixで確認できない情報を推測しない。
5. 3件表示の要件がある場合、最新順で3件になっていることを確認する。

## サービスやレビューを更新する場合

1. ココナラの該当商品ページを確認する。
2. 出版サポートと表紙デザインを別の商品として扱う。
3. 公開レビューだけを商品データへ紐づける。
4. レビュー出典リンクは商品カード内の独立した<a>にする。
5. 外側のカードリンクと入れ子になっていないことを確認する。

## UIを変更する場合

1. Home.tsxの該当セクションを特定する。
2. 既存のCSSクラス、Lucideアイコン、Framer Motionのパターンを確認する。
3. 情報階層、読みやすさ、キーボード操作、レスポンシブを維持する。
4. 1280px前後のデスクトップと375px前後のスマートフォンで確認する。
5. ブラウザコンソールの警告を確認する。

# 必須検証コマンド

変更後、少なくとも次を実行してください。

pnpm check
pnpm test
pnpm build

テストが失敗した場合、原因を直してから完了報告してください。画像・リンク・フォーム・外部データを変更した場合は、該当する表示と操作も確認してください。

# 完了時の処理

1. 実施した変更を要約する。
2. 未確認事項や外部サービス依存を明記する。
3. todo.mdの該当項目を完了にする。
4. 変更ファイルを一覧化する。
5. pnpm check、pnpm test、pnpm buildの結果を報告する。
6. UI変更ならデスクトップ・モバイル表示とコンソール確認結果を報告する。
7. 既存のMade with Manus表示はサイトコードではなくプレビュー／編集環境側のウォーターマークなので、アプリ側のCSSやJavaScriptで無理に削除しない。

ユーザーの指示が曖昧な場合、勝手に大量変更せず、変更対象・掲載範囲・外部情報の出典を確認してから実装してください。
