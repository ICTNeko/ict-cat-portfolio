# KindEd・ICTのねこ連携計画

## 1. 目的

既存の「ICTのねこ｜本と学びをデザインするポートフォリオ」を中心に、教育未来創造研究会KindEdの活動、講座・研修依頼、出版・デザイン相談、YouTube、Amazon、ココナラへの導線を一つの分かりやすい体験へ統合する。訪問者が「本を書いてみたい」「表紙を依頼したい」「KindEdの講座を依頼したい」という目的に応じて、迷わず次の行動へ進めることを成果目標とする。

## 2. 採用する前提

今回の計画では、アップロード済みのポートフォリオ引き継ぎ資料を主な仕様書として扱い、参照タスクの詳細本文には依存しない。KindEdアプリ本体の認証、データベース、権限管理、通知などはポートフォリオへ統合せず、公式サイトや専用アプリへの外部リンクとして分離する。ポートフォリオは静的フロントエンドを基本とし、無料で公開・更新しやすく、Gitベースの他AIエージェントでも編集可能な構成を維持する。

現在のApple風Liquid Glassデザインは維持する。ただし、引き継ぎ資料にある「本屋さん型」の情報設計を取り入れ、書籍を主役にした分類、KindEd共著本の独立表示、デザイン実績との明確な分離を行う。これにより、視覚表現は現行サイト、コンテンツ構造と更新ルールは引き継ぎ資料という役割分担にする。

## 3. 実装フェーズ

### Phase 1：情報設計と出典整理

`shared/const.ts`を公開コンテンツの単一管理場所として整理する。自著は`BOOKS`、KindEd共著本は`COLLABORATIVE_BOOKS`、制作実績は`PORTFOLIO_ITEMS`または`PROVIDED_COVER_ITEMS`、相談商品は`SERVICES`、動画は`YOUTUBE_VIDEOS`、イベントは`KINDED_EVENTS`、外部リンクと問い合わせ先は`SITE_CONFIG`へ分離する。確認できないASIN、レビュー、イベント情報は推測で補わず、Amazon検索URLまたは保留扱いにする。外部情報を追加する場合は確認URL、確認日、利用目的を`research/`へ記録する。

### Phase 2：ポートフォリオとKindEdの連携導線

Homeページに、書籍紹介、KindEd共著本、YouTube、デザイン実績、KindEd活動、講座依頼の順で情報階層を整える。KindEd共著本は自著棚とは異なるラベルとセクションで表示し、KindEdの公式サイト、イベントページ、問い合わせフォームへつなげる。KindEdの講座・研修依頼は専用フォームの相談種別として明確に表示する。

### Phase 3：サイト内問い合わせフォーム

フォームには名前、メールアドレス、相談種別、問い合わせ内容を設ける。相談種別には「KindEdの講座・研修依頼」「Kindle出版の相談」「書籍表紙デザインの相談」「その他のお問い合わせ」を用意する。標準実装ではバックエンドや外部APIを追加せず、入力内容を`mailto:`の件名・本文へ整形して、訪問者のメールアプリを開く。問い合わせ先は引き継ぎ資料に記載された`neyrateacher@gmail.com`を基準にするが、公開前に利用者本人が最終確認する。

将来、フォームをサイト内で完全送信したい場合は、Google Forms、Formspree、Netlify Formsなど無料枠のあるサービスを候補とする。ただし、個人情報の保存場所、通知先、利用規約、スパム対策を確認してから導入し、APIキーや秘密情報をフロントエンドへ直書きしない。

### Phase 4：URL不具合への代替導線

外部URLが開けない場合に備え、同じ目的へ到達できる代替導線を設ける。KindEdは公式ホームページ、Peatixイベントページ、メールフォームを併記する。YouTubeはチャンネルURLと動画個別URLを使い分け、Amazonは照合済みの直リンク以外を検索URLへ切り替える。ココナラが閲覧できない場合でも、問い合わせフォームから表紙デザイン相談へ進めるようにする。外部サイトの403やログイン要求はサイト側の障害と断定せず、リンクの確認日と代替手段を表示できる設計にする。

### Phase 5：AIエージェント向け運用整備

プロジェクトルートに`README.md`、`AGENTS.md`、`CLAUDE.md`、`docs/AI_HANDOFF.md`、`docs/HANDOFF_PROMPT.md`が存在する場合は、更新前に順番に読む。新しい変更は最初に`todo.md`へ未完了項目として追加する。公開コンテンツは`shared/const.ts`、表示構造は`client/src/pages/Home.tsx`、配色・レスポンシブは`client/src/index.css`に限定して変更し、サーバーやDBは要件がない限り変更しない。更新後は変更ファイル、出典、未確認事項、検証結果を報告する。

## 4. UI・アクセシビリティ要件

モバイル幅375px前後で横スクロールを発生させず、入力欄とボタンを十分な高さにする。ラベルと入力欄を明確に関連付け、必須項目を視覚とHTML属性の両方で示す。画像には内容に対応したaltを付け、外部リンクには必要に応じて`target="_blank"`と`rel="noreferrer"`を付ける。リンクの入れ子、ボタン内リンク、キーボード操作不能、フォーカス表示不足を避ける。アニメーションは短くし、`prefers-reduced-motion: reduce`で抑制する。

## 5. 検証計画

実装後は、少なくとも次のコマンドを実行する。

```bash
pnpm check
pnpm test
pnpm build
```

外部URLや画像を変更した場合は、リンク検査も行う。デスクトップ幅1280px前後とスマートフォン幅375px前後で、ナビゲーション、KindEd導線、問い合わせフォーム、入力エラー表示、メール作成画面への遷移を確認する。フォーム送信は実際のメール送信を自動実行せず、生成された宛先・件名・本文が正しいことを確認する。メールアドレス、ASIN、レビュー、イベント情報などの公開情報は、利用者本人の最終確認を経て公開する。

## 6. 完了条件

ポートフォリオから自著、KindEd共著本、YouTube、デザイン実績、KindEd公式サイト、講座依頼フォーム、ココナラ、問い合わせ先へ到達できること。フォームがスマートフォンで入力しやすく、メールアプリへ内容を引き継げること。現在のLiquid Glassデザインを維持しつつ、書籍とKindEdの情報が混在しないこと。さらに、他AIエージェントが引き継ぎ資料と`shared/const.ts`を読めば、出典確認・編集・検証を再現できることを完了条件とする。

## 7. 未確定事項とリスク

引き継ぎ資料には、過去のサイトURLと現在のプレビューURLが混在している可能性があるため、公開URLは実際の公開時点で確定する。KindEd共著本6冊、YouTube動画4本、イベント情報、ココナラ商品別レビューは、公開前に最新の公式ページで照合する。`mailto:`方式は訪問者のメールアプリ設定に依存するため、メールアプリがない環境向けに、返信先メールアドレスを画面上にも表示する。完全なサイト内送信が必要になった場合は、第三者フォームサービスまたは小規模なバックエンド導入を別途承認してから実装する。
